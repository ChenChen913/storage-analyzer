# 2026-07-15 优化案例：并行执行 + 应用卸载后重扫

## 场景

用户要求：
1. 卸载一个不再使用的 AI 编程助手（本地文件形式，无注册表安装记录）
2. 重跑全盘分析
3. 优化速度（"体验感有点差"）

## 操作：卸载应用

该应用共有 4 处分布，全部是本地文件：

| 位置类型 | 说明 |
|------|------|
| 家目录下的同名点目录 | 主数据目录 |
| 非系统盘根目录下的同名目录 | 独立的数据副本 |
| IDE A 的扩展目录 | 已安装的扩展版本 |
| IDE B 的扩展目录 | 已安装的扩展版本 |

**检查清单（卸载前必须确认）：**
1. 搜索所有 IDE 扩展目录（.vscode/.cursor/.trae-cn/.codebuddycn 等）是否安装了该扩展
2. 检查家目录、各盘根目录是否有同名数据目录
3. 检查 AppData/Local 和 AppData/Roaming 是否有残留
4. 检查 Windows 注册表是否有安装记录
5. 确认用户确实不再使用

删除后两个盘的使用量都下降，系统盘释放数 GB。

## 速度优化对比

### 第一轮（慢）
- 系统盘 scan 串行执行
- 非系统盘全量递归超时（不得不改用 drilldown）
- 18 个 drilldown 逐条串行
- **总耗时约 5 分钟**

### 第二轮（优化后）
- 系统盘 scan + 非系统盘 drilldown 并行
- 12 个 drilldown 每批 6 个并行
- 构建分析 JSON 直接复用上一轮模板
- **总耗时约 2 分钟**

### 关键优化手段

1. **系统盘 scan.py + 非系统盘 drilldown.py 同时后台跑**（terminal background=true + notify_on_complete=true）
2. **drilldown 一律 6 个并行**（每轮 6 个 terminal 调用）
3. **分析 JSON 复用模板**（只改 disk_used/disk_free 数字和受影响的条目，不从头写）
4. **等 scan 完成前就开始 drill**（系统盘扫完立刻 drill，不用等非系统盘）

## 副作用

删除大量文件后，scan.py 扫描变快（文件数减少）：第二轮耗时约为第一轮的六成。

## 验证

重扫确认：
- 该应用目录从用户目录 Top5 消失
- 两个盘的使用量均下降
- 两个 IDE 的扩展目录不再含该扩展
